# 투자회사 AI 에이전트 조직 설계

이 디렉터리는 한국투자증권 자동매매 시스템을 기반으로 한 "AI 투자회사" 운영 구조를 모델링한 예시입니다. 핵심 아이디어는 다음과 같습니다.

- 사장님은 최종 책임자
- 부장은 운영의 책임자
- 팀장은 실행을 구성
- 대리/사원은 근거를 수집하고 검증
- 리스크 부장은 사전 검증을 위해 프로젝트에 "딴지"를 걸고, 팀장/사원들은 그 딴지가 타당한지 자료와 근거를 확인한다

## 조직 구조

```text
CEO(사장님)
├── 투자부장
│   ├── 전략팀장
│   │   └── 전략분석 사원
│   └── 포트폴리오팀장
│       └── 포트폴리오 분석 사원
├── 리스크부장(사전 딴지 담당)
│   ├── 리스크팀장
│   │   └── 리스크 검증 사원
│   └── 규제/운영팀장
│       └── 근거 수집 사원
├── 운영부장
│   ├── 실행팀장
│   │   └── 주문/모니터링 사원
│   └── 고객운영팀장
│       └── 리포트/커뮤니케이션 사원
└── 기술부장
    ├── 데이터팀장
    │   └── 데이터/백테스트 사원
    └── 개발팀장
        └── 시스템/API 사원
```

## 핵심 프로세스: 리스크 딴지 검증

1. 리스크 부장이 프로젝트/전략/주문 로직에 대해 사전 이슈를 제기
2. 팀장과 대리/사원은 해당 이슈를 진단할 자료를 찾음
3. 과거 데이터, 로그, 백테스트 결과, 규제 문서, 위험 모델을 근거로 검토
4. 문제의 타당성을 증명하거나 반박
5. 승인 / 수정 / 보류 중 하나로 결론

예시:

- 리스크 부장: "모멘텀 전략은 시장 급락 시 손실 폭이 과하게 커질 수 있다"
- 리스크팀장: "시장 변동성 20% 이상 시나리오를 확인해 보자"
- 사원: "백테스트 3개월 데이터, VaR 계산, 최대 낙폭 수치, 과거 급락일 패턴을 검토한다"
- 결론: 승인 / 보완 / 거부

## 구현 원칙

- 모든 프로젝트는 리스크 딴지 검증을 통과해야 한다
- 딴지의 근거는 숫자, 로그, 문서, 백테스트 결과로 확인한다
- 최종 승인 권한은 관리자/사장님이 가진다
- 리스크 부장이 거는 문제는 "예외를 찾는 것"이 아니라 "사전에 막는 것"이다
